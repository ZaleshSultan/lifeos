# LifeOS update — 2026-10-05

## Что добавлено

- Ежедневный Telegram-дайджест: дела на сегодня, сегодняшние пары и дедлайны на ближайшие 7 дней.
- Время дайджеста настраивается через `DAILY_DIGEST_TIME` (по умолчанию `08:00`) и учитывает timezone профиля; fallback — `Asia/Almaty`.
- Защита от повторной отправки одной и той же дневной сводки через `daily_digest_deliveries`.
- Быстрые учебные действия в Telegram: пары сегодня, дедлайны, карта корпуса, силабусы, калькулятор, добавление дедлайна/темы.
- `/study today`, `/study deadlines`, `/study map`, `/study syllabi` и deep-link переходы в нужную вкладку TMA.
- Вкладка «Карта» со встроенной картой главного корпуса и внешним fallback-переходом.
- Вкладка «Силабусы»: редактор компонентов ATT1/ATT2/экзамена и весов для любого активного курса; неизвестные предметы стартуют с нейтральной схемы без выдуманных коэффициентов.
- Встроенные fallback-схемы калькулятора для `OS52-EN`, `DMS52-EN`, `K(RUSSIAN)L51-RU`, `CNC53-EN`, `DLD52-EN`.

## Что нужно применить на сервере

1. Обновить код и применить Supabase migrations, включая:
   - `20261005000100_daily_digest_deliveries.sql`
   - `20261005000200_seed_aitu_study_calculators.sql`
2. Создать `workers/daily-digest-worker/.env` по примеру `.env.example`.
3. При необходимости изменить `DAILY_DIGEST_TIME=08:00`; окно catch-up по умолчанию 720 минут.
4. Установить systemd unit из `workers/daily-digest-worker/lifeos-daily-digest.service.example` (пример настроен на `/home/zalewko/lifeos`).
5. Выполнить:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lifeos-daily-digest.service
sudo systemctl status lifeos-daily-digest.service
```

6. Пересобрать/redeploy bot и TMA обычным способом проекта.

Для безопасной первой проверки можно временно указать `DAILY_DIGEST_TEST_TELEGRAM_USER_ID=<your telegram id>`, чтобы worker слал дайджест только одному Telegram-пользователю.

## v4 — персональный Web, погода и Google Calendar

- `/weather <город>` геокодирует город через Open-Meteo и сохраняет координаты в `user_settings` отдельно для каждого пользователя. Погода показывается на главной TMA/Web и в ежедневном дайджесте.
- `/web` создаёт HMAC-подписанную ссылку, привязанную к `user_id`. Next.js меняет её на HttpOnly cookie и все запросы к LifeOS API выполняет от имени этого пользователя.
- Web `/today` и `/study` теперь загружают реальные персональные данные, а не общий статический экран.
- Google OAuth запрашивает `calendar.events`: новые LifeOS reminders создают события в `primary` Google Calendar пользователя; snooze обновляет событие, cancel удаляет его.
- Старые Google-подключения с `calendar.readonly` не ломаются, но UI просит один раз переподключить Google, чтобы выдать write-scope. Сам LifeOS reminder при ошибке Google всё равно остаётся сохранённым.

### Новые переменные окружения

В bot/root env:

```bash
LIFEOS_WEB_URL=https://web.example.com
LIFEOS_WEB_SESSION_SECRET=<random secret, e.g. openssl rand -base64 32>
```

В `apps/web/.env`:

```bash
LIFEOS_API_BASE_URL=https://api.example.com
NEXT_PUBLIC_LIFEOS_API_BASE_URL=https://api.example.com
```

Для daily digest погода берётся из пользовательской настройки `/weather`. Три `LIFEOS_DEFAULT_WEATHER_*` переменные являются только необязательным fallback и для multi-user режима их лучше оставить пустыми.

### Google после обновления

1. В Google Cloud должен быть включён Google Calendar API.
2. Redirect URI остаётся тем же `GOOGLE_OAUTH_REDIRECT_URI`.
3. Пользователям, подключавшим Google до v4, нужно один раз нажать переподключение Google в Sources/TMA, потому что старый token мог иметь только `calendar.readonly`.
4. После этого `/remind завтра 19:00 пойти в кино` создаёт и Telegram/LifeOS reminder, и событие в личном Google Calendar.

Новая схема БД для v4 не нужна: погода хранится внутри существующего `user_settings.settings`, а Google event id — внутри `reminders.metadata_json`.
