## Confirmed blocking findings

### P1 — V6-MIG-01: stale evidence can retain authorization for an exact grade forecast

[Migration 59:324](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106010000_academic_grade_events.sql#L324) removes each record's `updatedAt` from the semantic forecast key without encoding per-record temporal eligibility. The real [grade engine:306](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/packages/core/src/grade-target.ts#L306) rejects evidence that becomes older than 48 hours. The [final begin:485](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106010000_academic_grade_events.sql#L485) relies on the unchanged key.

Reproduction kept the changed grade, owner consent, source and lease fresh while a different mapped record crossed its 48-hour boundary after preparation. The existing credential-free formatter changed from an exact **39.00/100 earned** synthetic forecast to “exact forecast unavailable.” The candidate fingerprint stayed equal and the real durable begin authorized the old text. No sender was invoked.

Required correction: bind every contributing record's finite/not-future/fresh eligibility to the semantic fingerprint, using the existing engine policy. Decline the old numeric render at begin after expiry, while preserving harmless fresh refreshes, closed attempted/ambiguous receipts and safe zero-attempt reprepare behavior. Add a regression covering this boundary.

### P1 — V6-MIG-03: policy review can remove a working legacy assignment route

[Migration 59:287](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106010000_academic_grade_events.sql#L287) initializes intelligence preferences during policy review. [Migration 60:82](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106020000_academic_deadline_intelligence.sql#L82) suppresses the old assignment candidates whenever that preference row exists. [Python planning:61](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/workers/common/academic_notifications.py#L61) invokes the replacement planner only when the grade-events flag is ON.

Reproduction used the actual preference and policy-review RPCs with existing assignment consent, a fresh verified unfinished assignment and **master ON / grade-events OFF**. Policy-only review left assignment consent/offsets unchanged and grade/quiz consent OFF, but the real old planner cancelled one prepared reminder and queued none. The assignment remained eligible exclusively in the replacement planner, which this configuration does not invoke.

Required correction: make assignment cutover depend on an explicit compatible routing/planner contract. A policy-only review must not disable an existing opted-in assignment path. Test the flag matrix and actual planner cancellation/preparation without enabling flags, changing consent, duplicating senders/jobs or opening an unbound delivery path. Both flags OFF remains safely closed. The master switch, rather than the history/planning switch alone, is the current final-send kill switch.

### P2 — V6-MIG-02: existing groups consume the candidate cap before deduplication

[Migration 59:372](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106010000_academic_grade_events.sql#L372) takes the oldest five groups before [planning:421](https://github.com/ZaleshSultan/lifeos/blob/aa0162fe37e444b70b8479ab6b51214b899614eb/supabase/migrations/20261106010000_academic_grade_events.sql#L421) excludes existing jobs.

Reproduction established six eligible groups with fresh observations. The first five had prior-hour sent jobs; current-hour job count was zero. Those five still occupied the candidate cap, leaving no planning work for the unseen sixth group. This is not the intended five-new-jobs/hour cap.

Required correction: bound planning selection after receipt/dedup eligibility and retain a separately valid/keyed final-send eligibility check. Preserve deterministic bounded queries, the actual five/hour allowance and all sent/attempted/unknown receipts. Add the six-group regression. The separate deadline `LIMIT 5` was not classified as a defect without a distinct reproduction outside the intentional quota.
