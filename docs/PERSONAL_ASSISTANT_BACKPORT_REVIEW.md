## Implemented improvements

The Telegram command PR adds `/tomorrow`, `/nextclass`, `/afterclasses [tomorrow]` and `/deadlines verified`, with buttons in Study and each academic reply. It leaves the existing plain `/deadlines` path intact. New personal reads require the authenticated active owner's private chat. Callback identity is resolved from the clicking user at the existing boundary. Output escapes saved source text, bounds Telegram message length and retains incompleteness warnings.

The pure academic agenda projection consumes existing Concierge records; it generates no new recurring schedule. Campus dates use `Asia/Almaty` even when the profile timezone differs. Changed, expired or out-of-range timetable verification, missing confirmed teaching periods and confirmed holidays withhold regular classes. Only confirmed examination events appear; personal/university exams, `exam`/`examfx` and unknown end times retain their distinctions. No room-map verification is invented.

After-class windows reuse `buildPlanningInputs` and `buildDailyPlan`. Concierge occurrences replace the legacy weekly projection for this view. Calendar commitments, scheduled tasks and confirmed examinations block windows. Unknown ends/durations and truncated inputs withhold estimates. The displayed window ends at the existing planner's assumed 21:00 boundary, not a saved owner preference. Travel and unscheduled work remain unknown; the reply explicitly limits its claim to saved commitments. If today's finished classes are no longer in the Concierge's forward-looking response, their end time is not reconstructed.

The verified-deadline option requires a fresh configured LMS connection, a verified fresh assignment, an explicitly unsubmitted state and a future due time within 30 days. Schema 58 omits active status from the public Concierge assignment projection, so the command additionally intersects the existing active owner-scoped deadline reader by the existing SHA-256 assignment key and due instant, excluding linked grades. A missing or disagreeing row fails closed. Results say “current selection”; the legacy reader does not expose its pagination truncation flag. Stale/unavailable LMS data never becomes an assertion that there are no assignments. No migration was needed.

`/briefing tomorrow` sends the normal on-demand morning briefing first, then the confirmed tomorrow view after Telegram acknowledges the first reply. It does not retry an ambiguous secondary send. Default `/briefing`, evening/documentary briefings, the scheduled digest, renderer, settings and service units are unchanged. Telegram acknowledgement is not handset-delivery evidence.

The separate Moodle fix addresses this reproduced sequence: grade persisted → reminder insertion fails → next snapshot temporarily hides the score → same score reappears. Previously the hidden snapshot erased the pending retry marker while retaining the known numeric grade, permanently losing the alert. The fix preserves existing retry intent while the score is hidden, waits for a numeric score to return, and retains queue deduplication. Zero and positive grades are covered. It introduces no preference, notification capability, schema or delivery-protocol change.
