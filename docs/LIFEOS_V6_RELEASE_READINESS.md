A diagnostic process listing exposed an obsolete infrastructure credential in tool output; its value was not copied into source, documentation or evidence files. The subsequent [read-only security review](LIFEOS_V6_SAFE_INTEGRATION_REVIEW.md#production-concurrency-and-credential-evidence) verified that it was already revoked: its decoded secret differs from the current protected connector secret, the current provider secret matches the protected file, and no old-client connections were recorded. Historical retirement and negative-rejection evidence were checked. The earlier active-rotation blocker is superseded by that evidence; this mission did not rotate a credential or change a connector.

The obsolete unit's inline revoked token remains a maintenance-cleanup concern, with no credential values or service arguments published here. A separately authorized cleanup may interrupt connectivity. This is distinct from requiring another rotation of the current credential solely because the obsolete token appeared in diagnostics; [Cloudflare's token-rotation guidance](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/remote-tunnel-permissions/#rotate-a-compromised-token) also distinguishes new-connection revocation from retirement of existing connections.

Remaining product limits are explicit: the supported reviewed forecast policy is linear 30/30/40, the latest history view is bounded to 100 events, failed/unconsumed snapshot backlog needs operational monitoring, and unsupported academic rules remain conditional. A current source/enrollment review is required for policy confirmation; known course-date bounds must contain the campus day, while null bounds are permitted after explicit owner review. Unknown observations stay unknown even when the policy is confirmed. Stale/expired Moodle access is reported unavailable; this task did not reconnect or independently verify the owner's live LMS. Work links retain course context but open the existing unfiltered list. Arbitrary historical workout-detail selection is not added merely because navigation retains a `workoutId`.
